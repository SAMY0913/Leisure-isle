### OI-01 夜间室内「悬空加色球」伪影（原 L-6）

- **类别 / 严重度 / 状态**：产品视觉 / **S2** / 已决策不做（P8.1 既有，本轮 NO-GO）
- **表现**：夜间室内宽景机位下，`night_room_wide`（2560×1440）出现 3 个悬空亮黄球：①(412,424) 左窗框上方贴墙、②(1289,472) 壁炉/衣柜前空中（较大）、③(1259,562) 其下方较小。白天不可见；把 02(b) 调参后由「裁切白」降为「橙色热点」，但伪影本身仍在。
- **复现**：
  ```bash
  cd "D:/休闲小岛幻境/游戏工程"
  bash "D:/休闲小岛幻境/开发产物/p82/run_godot.sh" --path . --resolution 2560x1440 \
    --script res://tools/probe_p82_lights_visual.gd -- --mode=shots \
    --out="D:/休闲小岛幻境/开发产物/p82/02_lighting"
  ```
  然后看 `02_lighting/after/night_room_wide.png` 上述三点；逐盏归因用 `-- --mode=isolate3`（关掉 `L[13] fireplace` 后 ②③ 亮度分别降 57% / 63%）。
- **影响**：仅夜间室内宽景/近景可见，影响观感但不影响玩法与性能；属 P8.1 双池解析光（无阴影）在近距离墙面上的固有热点，被 glow 放大成球。
- **验收标准**：
  1. 同一机位同分辨率下，上述三点邻域（半径 12 px）与同墙面色差 ≤ 8/255，且不再呈圆形；
  2. `02_lighting/after/night_room_wide.png` 全帧近白像素（min>235）为 0；
  3. 壁炉暖光仍落在炉台/地板/上方墙面（hearth p99 ≥ 200、clip = 0，不许用整体调暗达标）；
  4. 五档画质各重拍一张夜间室内图，均无可见球；
  5. 新增自动化断言：室内夜间机位中不存在「半径 ≤20 px 的近白连通域且四周为墙面」的斑块。
- **证据**：`02_lighting/regress/{nodes,isolate2,isolate3}_diag.log`、`02_lighting/crop/night_ball*.png`、`02_lighting/report_crop/`。
- **修复边界**：不许只把 glow/自发光调暗来「藏」；不许改光槽位置（`probe_p82_fireplace` G8 契约）或改 16 槽双池架构（除非单独立项）。

### OI-02 门廊灯近景光团过曝（原 L-10）

- **类别 / 严重度 / 状态**：产品视觉 / S3 / 已登记未修（P8.1 遗留参数，本轮未动）
- **表现**：门廊灯罩 `self_lit=false`、`glow=1.0`（`scripts/cottage.gd:353`），近景形成大而糊的加色光团，白天/雪地背景下尤其抢眼；灯罩自发光与真实局部照明的比例失衡。
- **复现**：`probe_p82_lights_visual.gd -- --mode=shots`，看 `02_lighting/after/night_porch.png` 与 `after/day_*` 门廊近景；或 `probe_p81_lights.gd` 的门廊机位（`OUT_DIR` 已指向 `02_lighting/probe_p81_lights/`）。
- **影响**：门廊近景观感；不改就一直是「P8.1 已知过曝」。q0 下同样明显（灯罩在小画质档也保留 glow）。
- **验收标准**：
  1. 门廊近景 ROI（灯罩外接框外扩 40 px）近白像素（min>235）相对当前基线下降 ≥50%，且灯罩本体轮廓仍可辨（边缘梯度 ≥ 现状的 80%）；
  2. 门廊地面仍能看出暖光落地（门廊中心照度代理：该 ROI 平均亮度 ≥ 现状 −10%）；
  3. 五档画质门廊近景各 1 张，`max_white` 像素比例 ≤ 0.02（沿用矩阵探针阈值）；
  4. 不改灯位/能量契约（`probe_p81_lights` 147 项仍全通过）。
- **证据**：`02_lighting/after/night_porch.png`、`day_*`；`docs/P8_2_02_NOTES.md` 限制段。
- **修复边界**：允许调 `glow` / 灯罩材质基色 / halo 半径，不许改成实时 Light3D 阴影；不许影响 16 槽外池预算。

### OI-03 室内外双池照明在门洞/窗边的硬阶跃（原 L-7）

- **类别 / 严重度 / 状态**：产品视觉 / S3 / 已决策不做（02(d) 整体回滚）
- **表现**：室内池与室外池的选池在门洞、窗边形成硬边界（同一面墙上亮度阶跃），白天逆光时更明显。
- **复现**：`probe_p82_lights_visual.gd -- --mode=qa` 的三档 q0/q2/q4 组图；或 `02_lighting/after/day_door_inside.png`、`day_chand_*`；边界梯度量化：day 门洞 4.62、窗边 11.06（夜间 5.13 / 9.80）。
- **影响**：贴墙/门洞机位才明显；P8.2 的 (a)(b) 未让边界变差，但也没修好。
- **历史教训（必读）**：02(d) 曾实现 `g_indoor_band` 全局 shader 参数，但 `toon.gdshader` 的 global uniform 与 `main.gd` 的 `RenderingServer.global_shader_parameter_add` 注册时序不一致，产生 4,374 条 `Shader uses global parameter 'g_indoor_band', but it was removed at some point` WARNING 并污染了同期窗口 run，最终整体回滚（全树 grep `g_indoor_band` = 0）。再做必须 shader 与注册**同一次提交**。
- **验收标准**：
  1. 门洞/窗边沿法线方向的亮度梯度相对当前基线下降 ≥40%（day 与 night 各一组）；
  2. band 外区域与基线逐像素等价（max_abs_diff ≤ 2/255），band 内无新增条纹/色带；
  3. 无任何 shader WARNING（`grep -c "removed at some point" == 0`）；
  4. `probe_p81_lights` 147/147、`probe_p82_fireplace --mode=geom` 34/0、五档矩阵仍 PASS；
  5. 若帧代价 >386 µs（A/A 噪声 p90）则必须给出取舍说明。
- **证据**：`docs/P8_2_REFINEMENT_REPORT.md` §4.1(d)；回滚后 `git log --oneline -- shaders/toon.gdshader`。

### OI-04 无阴影解析光穿墙（OI-01 的根因，架构性）

- **类别 / 严重度 / 状态**：架构限制 / S3 / 已决策不做（本轮禁止改全局灯光架构）
- **表现**：16 槽解析光（`toon.gdshader` 的 `g_l0..g_l15`）按距离/法线着色，不做阴影与遮挡判定 → 壁炉/台灯可以「照到」墙背面、楼板上方，形成非物理亮斑（OI-01 的机制）。
- **复现**：`02_lighting/regress/isolate3_diag.log` 的逐盏关灯矩阵（关 `L[13]` 后墙热点消失）；或 `probe_p82_lights_visual.gd -- --mode=isolate2` 的 `nolights` 全黑对照。
- **影响**：所有近墙强光源都有同类风险，只是夜里、室内、近距离才被看见；改它等于加遮挡/阴影方案，属里程碑级。
- **验收标准（阶段目标，不是本清单的修复门槛）**：
  1. 产出一份「遮挡/衰减方案」评估：候选①屏幕空间接触阴影②逐光源球体遮挡近似③关键灯改用带阴影的少量 Light3D；给出 q0–q4 帧代价与显存估算；
  2. 至少在一个室内机位上证明 OI-01 三点消失且 OI-02 门廊暖光不倒退；
  3. 不引入 shader 全局参数时序问题（见 OI-03 教训）。
- **说明**：本轮把「不回到全套实时 Light3D 阴影」写进了任务纪律，故不修；此条只用于防止下一阶段误以为是新 bug。
